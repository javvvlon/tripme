# tripme_app

Frontend for TripMe: **prerendered landing** at `/` + **SPA agent CRM** at `/app/**`,
from one codebase. Implements §3.4 (hybrid rendering) and §3.5 (repo boundaries) of
`TripMe-Architecture-v5.md`.

Nuxt 4 · Vue 3 · TypeScript. No UI framework — the design tokens in
`app/assets/css/main.css` are derived from the TripMe logo (`#F68634`).

## Запуск

```bash
npm install
npm run dev            # http://localhost:3000
npm run build          # prod build
node .output/server/index.mjs
```

## Ключевые файлы

- **`nuxt.config.ts`** — `routeRules` со сплитом рендеринга. Здесь же `nitro.preset: 'node-server'`:
  API держит SSE-соединение ~20 с на поиск, serverless для этого не годится (§3.3).
- **`app/composables/useHotOffers.ts`** — шов между статикой и живыми данными.
  Сейчас возвращает образцы, поэтому `/` можно предрендерить. Когда появится
  `tripme_api`, меняется тело композабла и **одна строка** в `routeRules`:
  `'/': { prerender: true }` → `'/': { swr: 600 }`. Компоненты не трогаются.
- **`server/api/apply.post.ts`** — заглушка. В проде проксирует в `tripme_api`:
  писать в Postgres должен только он (§3.5, правило 2). Тело заявки намеренно
  не логируется — это персональные данные (§7.4).

## Чего здесь намеренно нет

- **Бэкенда.** Живёт в `tripme_api`. Nitro тут рендерит страницы и проксирует, не более.
- **Авторизации.** `better-auth` ставится вместе с API; куки — на `.tripme.uz` (§7.2).
- **Реального CRM.** `/app` — заглушка, помечающая маршрут и режим рендеринга.
- **Финальных цен и условий.** Всё, что про тарифы, помечено как непубличное.
  Не выкладывайте страницу с этими цифрами, пока не согласуете их.

## Что дальше

1. Заполнить настоящие контакты вместо `agents@tripme.uz` и `@tripme_uz`.
2. Подключить `/api/apply` к реальному приёмнику заявок.
3. Прогнать текст через живого агента-фрилансера — он единственный, кто скажет,
   попадает ли формулировка в его боль.
4. Домены: `tripme.uz` (лендинг) и `api.tripme.uz` — соседние поддомены,
   иначе куки сессии не будут работать (§3.5).
